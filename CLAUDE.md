# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A FastAPI boilerplate for **The Open Accelerator Healthcare Hackathon — Track 1: Federated Medical Imaging Search**. The repo simulates three siloed, unauthenticated hospital database nodes (BCH, MGH, BWH). It is intentionally "dumb": each node blindly serves its own local JSON study data, has no auth, and leaks PII (patient names, birthdates) by design. The hackathon challenge (not yet built in this repo) is to build an aggregation/search/privacy/access-control layer on top of these three nodes.

## Architecture

- `main.py` — single FastAPI app. On import, it reads the `HOSPITAL_NODE` env var (`BCH`/`MGH`/`BWH`), loads the matching JSON file from `data/` into memory, and validates every record against `StudyRecord`. There is no database and no persistence — the app is stateless and the dataset is fixed at process start (changing `data/*.json` requires a restart).
- `models.py` — the single Pydantic model, `StudyRecord`, defining the DICOM-style study schema (see field table in README.md). All fields are strings, including dates and ages.
- `data/{bch,mgh,bwh}_data.json` — 900 pre-generated study records per hospital (300 each of brain/heart/fetal). Same schema across all three files; `InstitutionName` and patient age ranges differ per hospital (BCH is pediatric 0–21, MGH and BWH are adult).
- The three "nodes" are the **same codebase** run three times with a different `HOSPITAL_NODE` env var and port — not three separate services.
- Because the app is a single process serving one hospital's data, any cross-hospital aggregation, search, or federation logic must live in a separate layer that calls all three nodes' HTTP APIs — it cannot be added inside `main.py` without breaking the single-node simulation.

## Running the nodes

Via devenv (preferred in this repo — `devenv.nix` defines all three as managed processes with health-check readiness on `/health`):

```bash
devenv up          # starts node-bch (:8001), node-mgh (:8002), node-bwh (:8003)
```

Manually (three separate terminals):

```bash
HOSPITAL_NODE=BCH uvicorn main:app --port 8001 --reload
HOSPITAL_NODE=MGH uvicorn main:app --port 8002 --reload
HOSPITAL_NODE=BWH uvicorn main:app --port 8003 --reload
```

Install deps: `pip install -r requirements.txt` (or let devenv's Python/venv integration handle it — `devenv.nix` points `languages.python.venv.requirements` at `requirements.txt`).

Verify a node is up: `curl http://localhost:8001/health` → `{"status":"healthy","node":"BCH"}`.

There is no test suite, lint config, or build step in this repo currently.

## API surface (per node)

- `GET /health` — node name + status
- `GET /api/studies` — all study records on that node
- `GET /api/studies/{study_id}` — single study by `StudyID`, or 404

There is intentionally **no search endpoint** and **no cross-node awareness** — each node only knows its own data. Interactive docs are auto-generated by FastAPI at `/docs` on each running node.
